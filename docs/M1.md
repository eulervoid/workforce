# M1: sync, device invites, daemon, fork (one human, many machines)

## Goal
The same workforce on a laptop, a cloud VM and a home desktop, all of one principal. Machines join with
an invite code, work offline, and converge when they reconnect, through NATs and without a server.
Every peer that has seen the same events has the same state, whatever the arrival order, duplication,
partitions or misbehaving devices. A lost machine is cut off with `wf fork`.

```sh
# laptop (holds the principal key)
wf invite device                          # prints wfi1...
# vm, inside a clone of the repo
wf join wfi1... --name vm                 # binds this machine to @joshua, syncs the log
wf daemon &                               # serves sync and join, follows gossip
wf item add --title "Try sync" --priority P1
# laptop, after being offline
wf sync                                   # one-shot, without a daemon
wf item list                              # shows the VM's item
wf device list                            # laptop, vm; last seen, flags
wf fork --exclude vm                      # the VM was lost: new workforce without it
```

## Scope
| In | Out (later) |
|---|---|
| `wf/sync/1`: version vectors plus fetch of missing parents by id | sessions, `Assigned`, `Claim`, leases, anchor dispatch (M2) |
| Admission of forked feeds (equivocation), flagged, never rejected | lane enforcement (M2, it only matters for claiming) |
| Device invites (`InviteCreated`, `DeviceBound`), `wf invite device`, `wf join` | member invites, `MemberJoined`, `OwnerAdded` (M4) |
| `DeviceProfile`, `wf device list\|edit`, `wf members` | progress from commits, overlap notifications (M2) |
| `wf daemon` with a unix socket, CLI falls back to the store without one | service installation (systemd, launchd); documented, not automated |
| `iroh-gossip`: heads and presence | `iroh-blobs` (M5) |
| `wf fork` excluding devices or members, optionally with a new principal key; `ForkAnnounced`, `wf fork accept\|list` | following a fork automatically |

Session events move to M2 together with the runner: a claim without a session has nothing to hold it,
and `Actor::Agent` needs one. M1 actors are `Human` only, as in M0.

## Crate layout
| Crate | Contents | Depends on |
|---|---|---|
| `wf-core` | new bodies, forked-feed admission, invite proofs, fork prefix rules, sync reconciliation as pure functions | as M0 |
| `wf-store` | `feeds` as a multimap, per-author tips | as M0 |
| `wf-net` (new) | sync and join protocols over any `AsyncRead + AsyncWrite`, iroh endpoint and member filter, gossip | `wf-core`, `wf-store`, `iroh` 1.x, `iroh-gossip`, `tokio` |
| `wf-daemon` (new) | socket server, storage task, peer loop | `wf-net`, `tokio` |
| `wf-cli` | new commands; daemon client with fallback to opening the store | all |

The protocols are written against generic streams, so the convergence tests run in memory without iroh.

## Format changes
All in the first work item, so the event format changes once. Existing workforces are recreated.

* **New body tags:** `4 InviteCreated`, `5 DeviceBound`, `6 DeviceProfile`, `7 ForkAnnounced`.
* **`MemberSeed`** gains `previous: Vec<PrincipalKey>`: principal keys this member used in the parent
  workforce, so prefix events keep resolving to the same handle after `wf fork --new-principal`.
* **Genesis** with `forked_from: Some(_)` becomes admissible (rules under *Fork*).

## Equivocation: admit both branches
Rejecting the second event with the same `(author, seq)` depends on which one a peer saw first, so two
peers could disagree forever. The realistic cause in UC1 is not an attack but a VM restored from a
snapshot that writes again from an old `seq`.

* **Admission:** `prev` is `None` exactly when `seq == 1`, otherwise an event by the same author with
  `seq - 1`. Nothing else about the feed is checked. Both branches are admitted, stored and relayed.
* **Fold:** unchanged. It is already a function of the event set ordered by `(hlc, EventId)`.
* **State:** per author a set of tips instead of one head. An author with two events at the same `seq`
  is flagged `Equivocated { seq }` (computed from the events, so every peer agrees once it has both).
* **Own feed:** a device that receives an event under its own key that it did not write (anything it
  writes is stored before it is sent) refuses to author further events and tells the user to join again
  as a new device. `wf status` shows the flag.
* **Store:** `feeds` becomes a multimap `(author, seq) -> {event id}`; `heads` holds the tips. The store
  checks that `prev` is present instead of a gapless head.

## Sync (`wf/sync/1`)
1. Both sides send a version vector `{author -> max seq}`.
2. Each sends the events of every author with `seq` above the other's maximum, in `(seq, id)` order,
   all branches included.
3. A received event whose parents are missing parks in the pending set as today. Its missing parent ids
   are requested with `Want{ids}` and answered from `events` by id. This repeats until nothing is missing
   or the other side does not have it.

Step 3 covers the cases a version vector cannot describe: a branch below the other side's maximum seq
(equivocation) and the parent prefix of a fork. Messages are length-prefixed postcard frames, versioned
by the ALPN.

* The device key is the iroh `SecretKey`, so the `EndpointId` is the `DeviceKey`.
* Every ALPN except `wf/join/1` rejects endpoints that are not bound devices of a member (gossip
  included). Addresses come from iroh discovery by `EndpointId`; `--relay <url>` overrides the relay.
* `wf sync` without a daemon dials every bound device once and reconciles with each one it reaches.
  Before the daemon exists, `wf sync --serve` keeps listening until interrupted.

## Device invites
Self-authorizing as in SPEC section 14, but with two changes.

* **The invite secret is a key pair.** `InviteCreated{kind: Device, invite: InviteKey, expires}` is
  signed by the principal and publishes the public key. `DeviceBound{invite: EventId, proof}` carries a
  signature by the invite key over `b"wf/invite/1\0"` + `(workforce, invite event id, device key)`. The
  log never contains something that would bind a *different* device.
* **Admission:** a `DeviceBound` is admissible only as its author's event with `seq == 1`, with the
  `InviteCreated` among its parents and a valid proof for its own author key. It binds the author to the
  invite's principal. A binding at the root of the device's own feed keeps "author is a bound device" a
  question about the causal past, and a device cannot be bound twice.
* **Expiry and single use are enforced at the handshake.** A member serving `wf/join/1` refuses a proof
  for an invite that is expired by its clock, already redeemed in its log, or reserved by a join in
  progress. Admission does not check them: expiry needs a clock and single use needs coordination.
* **Leftover case:** a leaked code redeemed twice, at the same time, through two members that cannot see
  each other. Both devices are bound, deterministically, and flagged `InviteRedeemedTwice` in
  `wf status` and `wf device list`. The fix is `wf fork --exclude <device>`.

**Invite code:** `wfi1` + base32 of `(workforce, invite event id, invite secret key, bootstrap endpoint
ids)`. The inviting device comes first in the bootstrap list.

**Join flow:** dial a bootstrap member on `wf/join/1`; send the proof (the connection authenticates the
device key); the member checks it and reserves the invite; the member streams the log; the joiner
authors `DeviceBound` and then its `DeviceProfile`, and pushes both; the member ends the reservation.

`wf invite device` needs the principal key, so in M1 it only works on the machine that ran `wf init`.
Joined machines never see the principal key.

## Device profiles
`DeviceProfile{name, hardware, agents: {agent -> max_sessions}, max_sessions}`, device-signed, last
writer wins per device. Nothing acts on `agents` and `max_sessions` until M2; they are set at join so
M2 does not need another prompt. `wf device list` shows the name, the principal, last seen (from gossip
presence, local only) and the flags. `wf members` lists principals, handles, roles and devices.

## Daemon
One daemon per machine (one device key, one iroh endpoint), serving every workforce stored on it.

* **Socket:** `$XDG_RUNTIME_DIR/workforce/daemon.sock`, falling back to the data directory. Requests
  name the workforce. Frames are postcard with a protocol version in the first message, so a CLI and a
  daemon from different builds refuse each other cleanly.
* **API: the daemon serves the replica, not commands.** `State` (snapshot bytes), `Event(id)`,
  `Events(filter)`, `Author{actor, body}` (policy check and signing in the daemon, against its current
  state). Rendering, drafts and prompts stay in the CLI unchanged. Transferring the state costs about the
  snapshot decode measured in M0 (~40 ms at 100k events); a typed query API replaces it if that grows.
* **Storage task:** one task owns the replica and receives writes over a channel (SPEC section 4).
* **Peer loop:** accept `wf/sync/1` and `wf/join/1`, join the gossip topic, sync with a peer whose heads
  are announced and differ, retry unreachable devices with backoff.
* Without a daemon the CLI opens the store directly as in M0. With one, the CLI never opens the store.

## Gossip
Topic `blake3("wf/gossip/1" || workforce id)`, bootstrapped from the bound devices. Messages carry
**hashes only**: `Heads{tips digest}` after every write and every 60 s as presence. A receiver whose
digest differs syncs with the neighbour over `wf/sync/1`. Presence is "last seen", kept in memory and
not part of the workforce state.

## Fork
`wf fork [--exclude <device|member>...] [--new-principal] [--name <name>]`.

* **Genesis** names `forked_from: {workforce, heads}`, the forker's current heads. Members are the
  parent's members minus the exclusions, with their devices minus the excluded ones.
* **Prefix:** parent events in the causal closure of `heads` are read-only history. They are admitted
  only when fetched by id from a known descendant (the fork heads or another prefix event), which is
  exactly sync step 3, and validated under the parent's rules. Item ids, comments and links carry over.
  Parent events after the fork point are never admitted.
* **New events** follow the child's membership, so an excluded device's prefix events stay and its later
  events and connections are rejected.
* **`--new-principal`** for when the lost machine held the principal key: the forker founds the child
  with a fresh principal key, and `previous` lists the old key.
* **Following:** `ForkAnnounced{to, members}` is written in the parent when the forker is an owner there
  (not with `--new-principal`: the old key is the one that is compromised). `wf status` shows it.
  Remaining devices follow by hand with `wf fork accept <id>`, which writes the new id to
  `.workforce.toml`. Automatic following waits until a fork is not a security event.
* `wf fork list` shows the parent, children and announcements.

## Work items, in order
Each ends with `cargo test` green and something runnable.

1. **Format changes and forked feeds.** New body tags, `MemberSeed.previous`, admission of forked feeds,
   per-author tips, `Equivocated` flag, own-feed detection, `feeds` multimap in the store, golden tests
   updated. Recreate the dogfood workforce.
2. **Sync protocol and simulation.** `wf-net` with `wf/sync/1` over generic streams, reconciliation
   logic in `wf-core`. A multi-peer simulation (in-memory duplex streams) with a proptest over random
   writes, partitions and reconnections.
3. **iroh transport and `wf sync`.** Endpoint from the device key, member filter, discovery, `--relay`,
   `wf sync` and `wf sync --serve`. Integration test with two local endpoints and relays disabled.
4. **Device invites and `wf join`.** `InviteCreated`, `DeviceBound`, invite code, `wf/join/1` with
   reservation, `wf invite device`, `wf join` (prompts and flags), the double-redemption flag.
5. **Device profiles.** `DeviceProfile`, written at join, `wf device list|edit`, `wf members`.
6. **Daemon.** `wf daemon`, socket API, storage task, peer loop, CLI client with fallback.
7. **Gossip.** Heads and presence, sync on mismatch, last seen in `wf device list` and `wf status`.
8. **Fork.** Fork genesis and prefix admission, `wf fork` with `--exclude` and `--new-principal`,
   `ForkAnnounced`, `wf fork accept|list`.
9. **Dogfood across machines.** Laptop and VM on this repo; README and `AGENTS.md` updated.

## Testing
* **Convergence:** generated schedules of writes on 3-5 peers with random partitions, reconnections,
  duplication and reordering end with identical `State` and heads on every peer.
* **Equivocation:** a device cloned mid-feed; every peer ends with both branches, the same state and the
  same flag; the cloned device stops writing.
* **Invites:** rejection test per admission rule (wrong proof, proof for another device, not seq 1,
  invite missing from parents); handshake refusals (expired, redeemed, reserved); concurrent redemption
  through two partitioned members ends with both bound and flagged everywhere.
* **Fork:** prefix fetched only by descent; parent events after the fork point refused; an excluded
  device's connection and events refused; `--new-principal` keeps handles in prefix events.
* **Transport:** two and three iroh endpoints in one process over loopback with relays disabled.
* **Daemon:** CLI against a running daemon gives the same output as against the store; mismatched
  protocol versions are refused.

## Exit criteria
* Laptop, VM and desktop (or three local peers in a test) join with invite codes, write while
  partitioned, and show identical `wf item list` and heads after reconnecting.
* The convergence property holds across at least 1,000 generated schedules.
* A device cloned from a snapshot is flagged on every peer and does not split them.
* `wf fork --exclude <device>` produces a workforce the excluded device cannot connect to, with all
  prefix items intact.
* A real sync between two machines behind different NATs, once direct and once through a relay
  (manual, recorded under *As built*).
* Joining a workforce with 100k events over loopback takes under 10 s.

## Risks
| Risk | Mitigation |
|---|---|
| Per-ALPN accept filtering is awkward in iroh 1.x, especially for gossip | wrap each protocol handler with the member check before handing over the connection |
| `iroh-gossip` (0.x) lags behind `iroh` 1.x | gossip only speeds things up; the daemon's periodic sync works without it |
| Transferring the state over the socket gets slow as logs grow | typed query API behind the same socket |
| A malicious member floods equivocations or pending events | members are trusted in v1; pending stays capped; flags make it visible |
| The principal key exists on one machine only | documented; a key-provider hook comes later |
| Clock skew makes invites expire early or late on the serving member | expiry is a coarse 24h window by default |

## Decided
* Dispatch, claims, leases and progress move to M2 with sessions.
* Single use of invites is a handshake guarantee, not an admission rule.
* Equivocation is admitted and flagged, never rejected.
* `wf fork` can exclude devices and replace the principal key.
