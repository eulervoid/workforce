# M0: event log, identity, item model (single peer)

## Goal
A single-machine `wf` that stores everything as signed events and folds them into the item model from
SPEC section 8. No networking, no agent runner. At the end, M1 only adds transport and M2 only adds
sessions; the event format should not change. `items` is a design reference only: no compatibility,
no import, we start fresh.

```sh
cd ~/src/some-repo
wf init --name demo                       # genesis, .workforce.toml, default agents from detected harnesses
wf item add "Implement feed sync" --priority P1
wf item add "Which hash for event ids?" --type question
wf item link k3f9 --depends-on q7x2        # task now computed as blocked
wf item list | show k3f9 | ready
wf item move q7x2 answered                 # task becomes ready
wf comment k3f9 "see #q7x2, @coder please keep it small"
wf item move k3f9 done && wf item archive k3f9
wf log                                     # raw events, verified
wf status
```

## Scope
| In | Out (later) |
|---|---|
| Event envelope with `actor`, canonical encoding, signing, verification | iroh, sync, gossip (M1) |
| Principal and device keys on disk, `owner`/`member`, genesis | invites, `wf join`, `DeviceProfile` (M1) |
| `AgentDefined`, `wf agent add\|list\|edit`, harness detection on `PATH` (no ACP probe yet) | sessions, worktrees, ACP runner (M2) |
| Item model: types, states, categories, built-in types, `depends_on`, `supersedes`, archiving | dispatch, claims, leases (M1) |
| Derived `references`, `mentions`, backlinks, `blocked_by`, readiness | inbox delivery to sessions (M2) |
| Policy as a principal-signed event, default policy with built-in types | lanes beyond a stored field, `wf fork` (M1) |
| In-memory fold, redb event store, snapshots | daemon, unix socket (M1) |
| CLI with `--json` | progress, search, decisions flow (M1-M3) |

Simplifications: one process, no daemon, the CLI opens the store directly with a short retry on the redb
lock. Out-of-order arrival is still handled in the fold (M1 depends on it) and tested with shuffled input.
Event types for later milestones (`SessionStarted`, `Heartbeat`, `Progress`, ...) are **not** defined yet;
`Unknown` handling makes adding them a non-breaking change. The `Actor::Agent{agent, session}` variant
**is** defined now, because it is part of the envelope.

## Crate layout

| Crate | Contents | Depends on |
|---|---|---|
| `wf-core` | ids, keys, `Actor`, `Event`, `EventBody`, encoding, signing, `Policy`, item model, mention/reference parser, validation, fold, `State`. **No IO, no async, no clock.** | `blake3`, `postcard`, `serde`, `thiserror`, `pulldown-cmark`, keys via `iroh-base` (verify) |
| `wf-store` | `EventStore` trait, redb implementation: events, feeds, pending, snapshots | `wf-core`, `redb` |
| `wf-cli` | `wf` binary: clap, output, `$EDITOR` flows, key files, harness detection | both, `anyhow`, `jiff` |

Spike first: `iroh-base` key types (`SecretKey`, `PublicKey`, `Signature`) so the device key is the iroh
`EndpointId` from day one. Fallback: `ed25519-dalek` plus a conversion in M1.

## Data model

### Keys and identity (`wf-core::identity`)
* `PrincipalKey`, `DeviceKey`: distinct newtypes. Mixing them up would let a device sign an
  authority event, which is the property the system relies on.
* Key files in `$XDG_DATA_HOME/workforce/keys/` (`principal.key`, `device.key`, mode `0600`).
  `wf init` creates both if missing. A key-provider hook (1Password, ssh-agent) comes later.
* `Actor::{Human(PrincipalKey), Agent{agent, session}}`. An agent actor always has a session, and
  sessions arrive in M2, so M0 only produces `Human`. Agents calling `wf` by hand in M0 act as their
  human. The `Agent` variant is still defined and encoded now, so the envelope does not change later.
* `AgentDefined{name, harness, model, capabilities, lanes}`, device-signed, name unique per principal.

### Event (`wf-core::event`)
Envelope as in SPEC section 6, including `actor`. `EventBody` has an `Unknown{tag, bytes}` variant.
Authority bodies carry an inner principal signature.

M0 bodies: `Genesis`, `PolicySet`, `AgentDefined`, `ItemCreated`, `ItemEdited`, `ItemTransitioned`,
`ItemLinked`, `ItemArchived`, `ItemUnarchived`, `Comment`.

### Policy (`wf-core::policy`)
Typed `Policy` parsed from TOML, stored verbatim in `PolicySet`. M0 uses `[types.*]` (states with
categories, initial state, allowed `depends_on` targets, fields, lane) and stores `[lanes.*]` and
`[assignment]` without acting on them. The default policy ships the built-in types `task`, `question`,
`decision`, `distill`. Validation: built-in type names and their states cannot be changed; each type has
exactly one `initial` state; every type with an `active` state also has an `open` state.

### Items (`wf-core::items`)
* `Category` enum (`Inactive`, `Open`, `Active`, `Blocked`, `Done`, `Cancelled`). Exhaustive matches
  everywhere: adding a category must break the build at every behaviour site.
* `Item`: stored fields per SPEC section 8; archived items fold into an `ArchivedItem` stub (enum
  variant, so code cannot accidentally read a body that is not loaded).
* Merge rules: LWW registers ordered by `(causal order, hlc, EventId)`, add-wins sets for `labels`,
  `requires`, `depends_on`.
* Computed: category, `blocked_by`, readiness (without sessions in M0), dependents ("required by"),
  cycle flags, unknown-state flags.
* Ids: short base32 prefix of the creating event hash, resolved like git prefixes (minimum 4).

### Text references (`wf-core::refs`)
Versioned parser over `pulldown-cmark` events, skipping code. Produces `#item` references and
`@principal`, `@principal/agent`, `@principal/agent/session` mentions; only tokens that resolve count.
In M0 mentions are computed and shown (`wf item show`, `wf mentions @joshua`), not delivered.

### Validation and fold
`validate(&State, &Event) -> Result<(), Invalid>`:
1. workforce id, version, signature;
2. `seq == prev.seq + 1`, `prev` is the author's last event;
3. author is a bound device of a member principal; authority bodies carry a valid principal signature
   with the required role;
4. body rules: item exists, type known, target state exists in the type, `depends_on` target type
   allowed, archive only from `done`/`cancelled`, `supersedes` only between decisions.

Events with missing `deps` wait in **pending**. Cycles from concurrent links are not rejected, they are
resolved in the fold (greatest edge ignored, flagged), because rejection would depend on arrival order.

`State::apply(&Event)` is deterministic over causal order. Property: **any causally valid permutation of
an event set yields the same `State`.**

## Work items, in order
Each ends with `cargo test` green and something runnable.

1. **Workspace skeleton.** Workspace with three crates, `flake.nix` (modelled on soundings),
   `justfile`. Spike: `iroh-base` keys build without the networking stack.
2. **Ids and encoding.** `EventId`, `WorkforceId`, `ItemId`, canonical postcard encoding, base32 display,
   prefix resolution. Golden-bytes tests.
3. **Keys, signing, actor.** Newtypes, sign/verify, principal-signed inner statements, key files.
4. **Event envelope and genesis.** `EventBuilder` (seq, prev, deps, hlc), `Genesis` with
   `forked_from: Option<ForkPoint>` (always `None` in M0), `Unknown` bodies round-trip.
5. **Policy.** Typed policy, default policy with built-in types, validation, `PolicySet`.
6. **Item model.** Categories, items, merge rules, archiving stubs, computed fields, readiness. Unit tests
   per category behaviour.
7. **Text references.** Parser, resolution, backlinks, mentions. Tests with code blocks, unknown tokens,
   ambiguous prefixes.
8. **Validate and fold.** Validation rules, pending set, fold, cycle resolution. Property tests
   (`proptest`): shuffled causal order gives identical state, concurrent edits converge, duplicate
   delivery is idempotent, invalid events are rejected with the specific error.
9. **Store.** `EventStore` trait and redb implementation: `events` by `EventId`, `feeds` by
   `(author, seq)` with gapless append, `pending`, `snapshots` keyed by covered heads, versioned.
   Append and snapshot write in one transaction. Lock retry for concurrent CLI calls.
10. **CLI.** `init` (keys, genesis, `.workforce.toml`, harness detection, default agents),
    `agent add|list|edit`, `item add|list|show|ready|edit|move|link|archive`, `comment`, `mentions`,
    `policy show|edit|apply`, `log`, `status`, `--json`. `item edit` uses a YAML draft in `$EDITOR`.
11. **Dogfood.** Track the M1 work of this repo in `wf` itself, and write an `AGENTS.md` section that
    teaches agents the M0 commands.

## Testing
* **Golden tests** for encoding and `EventId`s, so format changes are deliberate.
* **Property tests** for fold order-independence and idempotence: the core claim of the design.
* **Rejection tests** per validation rule, asserting the specific error variant.
* **Store tests** against the `EventStore` trait: gapless seq, snapshot equivalence, crash safety.
* **CLI tests:** parsing, default output, `--json` schema snapshots (`insta`).

## Exit criteria
* `wf init` plus the demo script above produces a log that verifies end to end.
* Deleting snapshots and running `wf status --refold` yields identical `item list` output.
* Startup with 100k events stays under 100 ms with a snapshot.
* Fold order-independence holds across at least 10k generated event sets.
* `--json` schemas are versioned and snapshot-tested.

## Risks
| Risk | Mitigation |
|---|---|
| Canonical encoding drifts and changes `EventId`s | golden tests, encoding in one module |
| LWW semantics surprise users | `item show --history` prints the events behind each field |
| Pending set grows with malformed deps | cap, expire, surface in `wf status` |
| `iroh-base` pulls in networking | `ed25519-dalek` plus conversion in M1 |
| Snapshot format changes with every state change | snapshots are a versioned cache; discard on mismatch and refold |
| Concurrent CLI calls hit the redb lock | short retry with backoff in M0; the daemon serializes writes from M1 |
| Policy changes strand items in removed states | keep the state, flag as unknown, `wf status` lists them |

## Decided
* Keys on disk for M0, both principal and device.
* Item ids: short base32 prefix of the creating event hash.
* No `items` compatibility or import.
