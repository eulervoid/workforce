# M0: event log, authority, items (single peer)

## Goal
A single-machine `wf` that stores everything as signed events and folds them into an `items`-compatible
state. No networking. At the end, M1 only has to add transport; the data model should not change.

```sh
wf init --name demo            # genesis, prints workforce id
wf item add --title "Fix parser bug" --priority P1
wf item list | show <id> | ready
wf item update <id> --state in_progress
wf comment <id> "looks like the lexer"
wf log                         # raw events, verified
wf status
```

## Scope
| In | Out (M1+) |
|---|---|
| Event, genesis, canonical encoding, signing, verification | iroh, sync, gossip, invites |
| Principal and device keys, delegation, `owner`/`member` | anchor, dispatch, claims, leases |
| Items domain ported from `items` (types, states, parent, depends_on, cycles, ready) | lanes, progress, git |
| Policy as a principal-signed event, default policy | `wf fork`, ACP, search |
| In-memory fold, redb event store, state snapshots | daemon, unix socket |
| CLI: `init`, `item *`, `comment`, `log`, `status`, `--json` | agents |

Simplifications: one process, no daemon, CLI opens the store directly. Out-of-order arrival is still
handled in the fold (M1 depends on it), and tested with shuffled input.

## Crate layout
Cargo workspace, so the pure domain stays free of IO.

| Crate | Contents | Depends on |
|---|---|---|
| `wf-core` | ids, keys, `Event`, `EventBody`, canonical encoding, signing, `Policy`, validation, `ItemsState` fold. **No IO, no async.** | `blake3`, `postcard`, `serde`, `thiserror`, `ed25519` via `iroh-base` (verify) |
| `wf-store` | `EventStore` trait and its redb implementation: events, pending, heads, snapshots | `wf-core`, `redb` |
| `wf-cli` | `wf` binary: clap, output, `$EDITOR` flows, key files | both, `anyhow` |

Decision to verify first: use `iroh-base` key types (`SecretKey`, `PublicKey`, `Signature`) so the device
key is the iroh `EndpointId` from day one, versus raw `ed25519-dalek` plus a conversion in M1. Preferred:
`iroh-base`, provided it builds without the networking stack.

## Data model

### Keys (`wf-core::keys`)
* `PrincipalKey`, `DeviceKey`: distinct newtypes over a public key. Mixing them up would let a device
  sign an owner-only event, which is exactly the property this system relies on.
* `Delegation` signed by the principal over `(principal, device, kind, labels, expires)`.
* Local key files under `$XDG_DATA_HOME/workforce/keys/`: device key always on disk; principal key on
  disk for M0, with a `--principal-key-cmd` hook later for 1Password.

### Event (`wf-core::event`)
As in SPEC section 6. `EventBody` is a non-exhaustive enum with an `Unknown{tag, bytes}` variant for forward
compatibility. M0 bodies: `Genesis`, `MemberAdded`, `DeviceBound`, `PolicySet`, `ItemCreated`,
`ItemFieldSet`, `ItemTransition`, `Comment`.

### Validation (`wf-core::validate`)
Pure function `validate(&WorkforceState, &Event) -> Result<(), Invalid>`:
1. workforce hash matches, version known, signature valid;
2. `seq` is `prev.seq + 1` and `prev` is the author's last event;
3. author is a bound device of a member principal;
4. body-specific permission (owner-only bodies need a principal-signed event from an owner);
5. body-specific rules (item exists, state allowed by item type, no dependency cycle, parent rules).

Events whose `deps` are not all present yet are kept in a **pending** set, not rejected.

### Fold (`wf-core::fold`)
`ItemsState::apply(event)`, deterministic over the causal order with ties broken by `(hlc, EventId)`.
Field updates are last-writer-wins per field. Property: **any permutation of a valid event set that
respects causality yields the same state.**

### Items (`wf-core::items`)
Port of `items` `item.rs` and `config.rs`: `Item`, `State`, `Priority`, item type config (states,
`allow_parent_of`, `allow_depends_on`), readiness, cycle detection. Item types live in the policy.
Adaptation: ids derive from the creating event hash (short base32 prefix, lengthened on collision).

## Work items, in order
Each ends with `cargo test` green and something runnable.

1. **Workspace skeleton.** `Cargo.toml` workspace, three crates, `rust-toolchain.toml`, `flake.nix`,
   `AGENTS.md`, CI-free `justfile` or `cargo xtask`-less scripts. Spike: confirm `iroh-base` keys build alone.
2. **Hashes, ids, canonical encoding.** `EventId`, `WorkforceId`, postcard canonical encoding with
   golden-bytes tests so the format is frozen deliberately.
3. **Keys and signing.** Newtypes, sign/verify, `Delegation`. Tests: wrong key, tampered body, principal
   vs device mix-up fails to compile or verify.
4. **Event and genesis.** Structs, build helpers (`EventBuilder` assigning `seq`, `prev`, `hlc`), `Genesis`
   with `forked_from: Option<ForkPoint>` present but always `None` in M0.
5. **Policy.** `Policy` struct, default policy from SPEC section 15 (only the parts M0 uses), `PolicySet` event,
   owner-only enforcement.
6. **Items domain port.** Move `items` domain code over (without its SQLx storage), add transitions and comments as events.
   Port its domain tests.
7. **Validate + fold.** `validate`, pending set, `fold`. Property tests with `proptest`: shuffled causal
   order gives identical state; concurrent `ItemFieldSet` converges; duplicate delivery is idempotent;
   tampered or unauthorized events are rejected.
8. **Store.** `EventStore` trait (append, get by `EventId`, range by `(author, seq)`, heads, pending,
   snapshot load/save) with a redb implementation. Tables: `events` keyed by `EventId`, `feeds` keyed by
   `(author, seq)` (gapless seq enforced on append), `pending`, `snapshots` keyed by covered heads.
   Append and snapshot write happen in one transaction. Test that snapshot plus newer events equals a
   full refold.
9. **CLI.** `init`, `item add|list|show|update|edit|ready|close`, `comment`, `log`, `status`, `--json`.
   `item edit` reuses the `items` YAML flow. Output formatting ported from `items`.
10. **Import.** `wf item import --from-items <path>` reads an `items` export so the existing tracker can be dogfooded.
11. **Dogfood.** Track the M1 work of this repo in `wf` itself.

## Testing
* **Golden tests** for encoding and `EventId`s (format changes must be deliberate).
* **Property tests** for fold order-independence and idempotence (the core claim of the design).
* **Rejection tests** per validation rule, asserting the specific error variant.
* **Store tests** for gapless seq, snapshot equivalence, crash safety (transactional append + snapshot),
  run against the `EventStore` trait so a second backend can reuse them.
* **CLI tests** as in `items`: parse, default output, `--json` schema snapshot.

## Exit criteria
* A fresh `wf init` plus a scripted session produces a log that verifies end to end.
* Deleting the snapshots and running `wf status --refold` yields identical `item list` output.
* `wf` startup with 100k events stays under 100 ms with a snapshot.
* Fold order-independence holds across at least 10k generated event sets.
* `--json` output schemas are versioned and snapshot-tested.

## Risks
| Risk | Mitigation |
|---|---|
| Canonical encoding drifts and changes `EventId`s | golden tests, encoding isolated in one module |
| LWW field semantics surprise users | `item show --history` prints the events behind each field |
| Pending-set growth with malformed deps | cap, expire, and surface in `wf status` |
| `iroh-base` pulls in networking | fall back to `ed25519-dalek` plus conversion in M1 |
| Snapshot format changes with every state change | snapshots are a cache: version them, discard on mismatch, refold |
| redb is single-process (CLI and daemon both open it) | M0 has no daemon; from M1 the CLI goes through the daemon socket |

## Decisions needed before starting
1. Principal key storage in M0: plain file with a clear warning, or require 1Password from the start.
   Recommended: file for M0, hook later.
2. Id style: short base32 from the event hash (proposed) versus nanoid as in `items`.
